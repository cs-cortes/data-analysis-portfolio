# Online Shop SQL Analysis

## Project Overview

This project analyzes data from an e-commerce business using PostgreSQL and SQL to identify patterns in customer behavior, sales, and product performance.

The project uses a relational database containing information about customers, orders, order items, products, suppliers, payments, reviews, and shipments.

The analysis focuses on data exploration, customer segmentation, product performance, revenue analysis, and product ranking using SQL. Python and Jupyter Notebook are used for data profiling and visualization.

## Objectives

* Analyze customer purchasing behavior and spending patterns.
* Segment customers based on their total spending.
* Identify the products generating the highest revenue.
* Analyze product performance within each category.
* Apply SQL techniques to extract and transform information from a relational database.
* Present the main findings using clear and reproducible analysis.

## Dataset

The project uses the **Online Shop 2024** dataset by Martha Dimgba, a relational e-commerce dataset designed to simulate an online shopping business.

The database contains eight related tables:

| Table         | Description                     |
| ------------- | ------------------------------- |
| `customers`   | Customer information            |
| `orders`      | Customer orders                 |
| `order_items` | Products included in each order |
| `products`    | Product information             |
| `suppliers`   | Supplier information            |
| `payments`    | Payment information             |
| `reviews`     | Product reviews                 |
| `shipments`   | Shipment information            |

The dataset contains approximately:

* 10,000 customers
* 15,000 orders
* 20,000 order items
* 2,000 products
* 100 suppliers
* 15,000 payments
* 1,106 reviews
* 15,000 shipments

## SQL Analysis

### 1. Customer Analysis

Customer spending was analyzed by joining the `customers` and `orders` tables.

The analysis calculated:

* Number of orders per customer
* Total spending per customer

`LEFT JOIN` and `COALESCE()` were used to ensure that customers without orders were also included in the analysis.

The analysis showed that the customers with the highest total spending had only two orders each, indicating that a high total spend is not necessarily associated with a high number of orders.

### 2. Customer Segmentation

Customers were segmented according to their total spending using `CASE WHEN`.

Three spending segments were defined for this analysis:

* **High:** ≥ $7,000
* **Medium:** ≥ $3,000 and < $7,000
* **Low:** < $3,000

The resulting distribution was:

* Low: 42.55%
* Medium: 38.50%
* High: 18.95%

A CTE was used to separate the calculation of customer spending from the subsequent segmentation analysis.

### 3. Product Analysis

Product performance was analyzed by joining `products` with `order_items`.

The analysis calculated:

* Units sold
* Revenue generated by each product

The product with the highest revenue was **Water Bottle**, generating $63,822.93 from 92 units sold.

The analysis also showed that the product with the highest number of units sold does not necessarily generate the highest revenue. For example, **Wireless Mouse** sold 118 units but generated $53,935.18 in revenue.

### 4. Product Ranking

Products were ranked within their respective categories using the `RANK()` window function and `PARTITION BY`.

The analysis identified the highest-revenue product in each category.

This analysis demonstrated how window functions can be used to perform rankings while maintaining category-level context.

## Key Findings

* The three highest-spending customers each placed only two orders, showing that order frequency alone does not explain total customer spending.
* Most customers belong to the Low or Medium spending segments, representing 81.05% of the customer base.
* Water Bottle generated the highest revenue among the analyzed products, despite not having the highest unit sales.
* Wireless Mouse sold more units than Water Bottle but generated less revenue.
* Multiple products can share the same product name, making `product_id` important for uniquely identifying products.
